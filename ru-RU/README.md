# SilentSafe

SilentSafe — это система защиты для персональных устройств, созданная **SilentStudio**.

- **Версия**: v1.0.0
- **Платформа**: Windows

> Этот репозиторий предназначен только для презентации проекта и **не содержит исходный код**.

## Возможности

- Сканирование файлов на безопасность (многопоточное + ускорение на Rust)
- Мониторинг системы в реальном времени (зарегистрирован как служба Windows; автоматический перезапуск при сбое; защита продолжается после выхода из приложения)
- Карантин
- Поведенческая защита (процессы / реестр / сеть)
- Глубокое обнаружение инъекций (ETW-TI)
- Защита включена по умолчанию, интерфейс показывает только результаты и скрывает технические детали

## Технологический стек

Python + PySide6 + QFluentWidgets + C++ сканирующий движок + Rust-ускорение

## Архитектура

- **UI-слой**: Python + PySide6 + QFluentWidgets; многостраничная навигация (Главная / Советы / Сканирование / Защита / Поведение / Карантин / Уведомления / Настройки); светлая/тёмная тема и акцентный цвет; мгновенное переключение языка (zh/en).
- **Движок сканирования**: C++ (SilentSecurityEngine), многопоточное параллельное сканирование, потоковый вывод прогресса и результатов в формате JSONL; режимы: файл / каталог / все диски.
- **Ускорение**: Rust (`ss_rust.pyd`, PyO3) выполняет пакетный разбор и агрегацию JSONL-вывода движка, примерно в 3 раза быстрее построчного разбора на Python; при отсутствии автоматически переходит на чистый Python (семантика идентична).
- **Мониторинг в реальном времени**: Windows `ReadDirectoryChangesW` (событийный), рекурсивно по всем фиксированным дискам; подтверждённые сигнатурные угрозы удаляются автоматически, эвристические — помещаются в карантин.
- **Поведенческий мониторинг**: создание процессов через ETW (0 задержки, соответствует `NtCreateProcess`; при недоступности — опрос); автозагрузка реестра и исходящие соединения — по разнице снимков; события несут PID / родительский PID / цепочку поведения.
- **Служба Windows**: движок зарегистрирован как служба (SCM, автозапуск) с политикой перезапуска при сбое (5с / 10с / 60с); отделён от процесса UI — защита продолжается после выхода, а SCM перезапускает службу при принудительном завершении.
- **Песочница**: опасные исполняемые файлы при неудачном карантине автоматически запускаются в изолированном процессе, повторно оцениваются по собранному поведению и снова помещаются в карантин.
- **Проверка подписи**: офлайн-проверка Authenticode через WinVerifyTrust + извлечение подписанта (без проверки отзыва, без сети); действительные подписи Microsoft / Google полностью доверяются, остальные действительные — понижаются с указанием подписанта.
- **Глубокое обнаружение инъекций**: ETW-TI (сессия ядра AutoLogger, Windows 11).
- **Модель связи**: UI и движок слабо связаны через JSONL — сканирование через stdout-канал; в режиме службы события мониторинга/поведения пишутся в файлы и читаются UI инкрементально.
- **Карантин**: файлы перемещаются в карантинный каталог с переименованием для предотвращения повторного запуска; поддерживаются список / восстановление / удаление; карантин и логи исключены из сканирования.
